# Tickets: GitHub issues on aidanwolter3/the-construct

Sessions stay targeted to one task; anything else becomes a ticket. A ticket must let a fresh session start cold:
it will have this repo and CLAUDE.md, but none of the current conversation.

## Filing a ticket

1. Check for duplicates first: `gh api -X GET search/issues -f q='repo:aidanwolter3/the-construct is:issue is:open <keywords>'`.
   If one exists, add what's new to it instead (update its body) and say so.
2. Create it with the GitHub MCP `issue_write` tool (`method: create`). Labels: `bug` (something is wrong) or
   `enhancement` (anything else). Title: the problem, not the fix, in plain words.
3. Body, in this order (keep it short; paths and names over prose):
   - `## Problem`: what happens, where (file paths, functions, endpoints), how it was found (PR #, command and
     its error output verbatim when short). Link the relevant `docs/DECISIONS.md` entries (Dnn).
   - `## Suggested fix`: the approach you'd take and the files it touches. Mark guesses as guesses.
   - `## Done when`: one or two checkable outcomes (a command that passes, a behavior on screen).
   - Note if it needs the developer's Mac (Android/device checks, the macOS window): cloud sessions can't do those.
   - End with the attribution footer:
     ```

     ---
     _Generated by [Claude Code](https://claude.ai/code)_
     ```
4. Add the start link: once you have the issue number N, update the issue (`issue_write`, `method: update`, the
   full body) so its first line is a link that opens a new Claude Code session on it:
   ```bash
   python3 -c "import sys,urllib.parse as u; n=sys.argv[1]; p=f'Work on GitHub issue #{n} (https://github.com/aidanwolter3/the-construct/issues/{n}). Read the issue and its comments first, then fix it and open a PR that says Fixes #{n}.'; print('https://claude.ai/code?'+u.urlencode({'prompt':p,'repositories':'aidanwolter3/the-construct'},quote_via=u.quote))" N
   ```
   First line of the body: `**[▶ Start a Claude Code session on this issue](<that URL>)**`, then a blank line.
5. Tell the user the issue number and link in one line. Don't start working on it in this session. If they ask
   to start it now, use `create_session` with the same prompt instead of the link.

## Picking up a ticket ("fix issue #N")

1. Read the issue and its comments (`issue_read`), then the files and decisions it names.
2. Work on the session's designated branch; reference the issue in commits and the PR body (`Fixes #N`) so it
   closes on merge.
3. If the ticket turns out wrong or bigger than described, comment on the issue with what you found before
   changing course.
